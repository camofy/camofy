# 身份订阅用量聚合（已批准，v0.1.1 实施）

## 目标和现状

身份的订阅 URL 在返回 YAML 时附带 Clash Verge Rev 能识别的用量响应头；统计对象是该身份启用的上游订阅套餐，不是设备实时网速或仅经 Camofy 消耗的流量。不采集客户端流量日志。

当前 `src/cloud/security.rs::fetch` 仅返回 YAML 文本，`worker.rs` 不保存上游用量，`sync.rs::artifact_response` 未输出 `Subscription-Userinfo`。仓库内 Clash Verge Rev 的 `src-tauri/src/config/prfitem.rs` 已按该头读取 `upload`、`download`、`total`、`expire`，所以应补全云端元数据链路，而不是修改 YAML 或客户端。

## 1. 获取和保存

- 沿用订阅 Profile 已配置的代理、定时刷新及手动刷新链路，在同一次请求中读取最终成功响应的用量头，不另发请求、不绕过代理，不因客户端下载订阅而向机场请求。
- 优先读取标准 `Subscription-Userinfo`；兼容明确列入白名单的 `x-amz-meta-`、`x-obs-meta-`、`x-cos-meta-subscription-userinfo` 形式。标准头和别名冲突时以标准头为准，同优先级冲突则标记无效。
- 严格解析非负十进制整数（字节、Unix 秒），限制头长、拒绝重复字段和溢出；未知字段忽略。缺失不补成 0。`total=0` 不擅自等同无限流量，而是额度未知，除非供应商适配器能明确证明其语义。
- 在订阅 Profile 的加密数据中保存服务器专属 `usage`：`upload_bytes`、`download_bytes`、`total_bytes`、`expire_at`、`observed_at`、`source_fingerprint`、`status`。编辑 API 不接受用户伪造或覆盖这些统计字段。
- 传输/HTTP 失败：保留最后有效快照并标记陈旧。HTTP 成功但头缺失/无效：当前状态记为缺失/无效，旧值仅供历史参考，不无期限冒充新值。URL 改变时立即使旧用量失效；仅改代理不意味着套餐改变。
- 有效用量头与 YAML 校验分别记录：即使本次 YAML 无效，也可更新成功响应中的有效用量，但继续保留上一份有效配置。用量回落可能是周期重置，不取历史最大值。

## 2. 参与范围、去重及计算

仅遍历身份中 `enabled=true` 且 `type=source` 的关联；独立配置 Profile、系统 Profile、禁用订阅不参与。节点数量、节点合并去重结果均不影响套餐用量。

按租户内的“额度池”去重：

1. 同一个 Profile 只计一次。
2. 相同完整上游 URL 自动视为同一额度池（仅规范化协议、主机及默认端口，不重排或丢弃查询参数；URL 摘要使用租户隔离的 HMAC，不能跨租户关联）。
3. 同一账号有不同订阅链接时无法可靠自动识别。为订阅 Profile 提供可选“共用额度池”设置，用户可显式归组；不按机场域名或节点重合度猜测。
4. 同池取最新有效快照，不累加；同时间数据冲突则显示异常。只从当前身份启用的成员读取，不引入其他身份或用户的记录。

设去重后每池的上传、下载、总额为 `uᵢ`、`dᵢ`、`tᵢ`：

| 字段 | 算法 |
| --- | --- |
| upload | Σ uᵢ |
| download | Σ dᵢ |
| total | Σ tᵢ |
| 已用 | upload + download |
| 各套餐剩余之和（云端明细） | Σ max(tᵢ − uᵢ − dᵢ, 0) |

不裁剪上游已用值，不制造无限额度；加法用 checked arithmetic，溢出时不输出伪造结果。各套餐并不能互相借用额度，客户端的“总量”只是汇总展示；一套餐耗尽仍应在云端单独告警。不同计费周期也保留各自明细，不尝试推算共同周期。

## 3. 缺失、陈旧和到期：建议默认值

- **完整性优先**：只有所有额度池都有有效、有限且未超过可用时限的 upload/download/total 时，才发送完整聚合头。部分缺失时不把缺失源当 0，也不把已知小计伪装为总体；云端仍显示“已知小计，2/3 套餐有数据”和逐项原因。
- **刷新失败**：最后有效值可短期使用，云端显示快照时间和陈旧标识。建议可用时限 `max(2 × interval_seconds, 1 小时)`，超过后不再发送该身份的聚合头；关闭自动刷新也不代表缓存永久有效。
- **到期时间**：单池或所有池的已知到期日一致时输出 `expire`。多池到期时间不同、存在未知/无限期时不输出 `expire`，客户端显示“—”；云端显示最近到期时间以及各池明细。不能把“最早一个套餐到期”伪装成“整个身份失效”。已到期套餐继续参与所绑定套餐的用量汇总，并在云端标记已到期，不暗中移除。
- 无启用订阅（只有配置 Profile）不发送用量头。

若希望客户端始终显示一个数字，可另选“只聚合已知额度”的宽松策略，但它会漏算未知套餐，**不建议作为默认值**。

## 4. 返回客户端与缓存

示例（100 MiB 上传 + 900 MiB 下载，总额度 10 GiB）：

```http
Subscription-Userinfo: upload=104857600; download=943718400; total=10737418240
Profile-Update-Interval: 1
Cache-Control: private, no-cache
```

- 所有公开身份订阅格式共用同一聚合逻辑，GET/HEAD 一致。旧域名保持原路径重定向，新域名最终响应携带元数据。
- 聚合可在当前有效身份的元数据上生成，不需要重新下载/解析 YAML。用量变化不创建配置 revision、不重启 Mihomo、不广播配置变更。
- 公开订阅的 ETag 改为 `hash(配置制品 hash + 聚合用量及其可用性)`；用量变化或状态从有效变成不可用时返回 200，避免客户端因旧 ETag 得到 304 而不更新卡片。未变化的 304 仍附带当前可用元数据头。
- Agent 同步接口继续使用原有配置 hash / revision，不能被公开订阅的元数据 ETag 影响。
- 一次响应使用一致的身份关联、制品和用量快照；身份编辑/发布失败时不得把未生效关联的用量配到旧 YAML 上。需要为已发布版本保存参与订阅 ID 清单，读取这些 ID 的最新用量。
- 可附带 `X-Camofy-Usage-Status`、`X-Camofy-Usage-Updated-At` 供诊断；客户端不一定认识这些扩展头，所以错误解释必须在云端 UI 呈现。
- 客户端只会在刷新订阅时更新数据，不是实时流量仪表。服务器现有上游刷新周期决定准确度，不能因为返回一小时建议刷新头就声称每小时已向机场取新数据。

## 5. 页面和接口

- 订阅详情：已用/总额、上传/下载、到期、上次取得时间、状态、额度池归属。
- 身份详情：“套餐额度汇总”卡片，显示统计覆盖率、已知小计、最近到期及明细；标明“来自机场，包含其他客户端用量”。
- 身份统计只读接口，做租户隔离；公开订阅头仅暴露四个标准聚合数值，不暴露上游 URL、账号、代理凭据或完整明细。
- 编辑额度池或启禁订阅立即重新计算显示和公开元数据；不额外触发携趣提取或上游下载。

## 6. 验收

1. 单订阅数据与机场原始头一致；两个不同套餐按整数精确相加；配置 Profile 不参与。
2. 禁用源不计、同 URL/同额度池不重复计；跨租户不串数据。
3. 覆盖缺字段、负数、超大整数、重复字段、多头冲突、total=0、过期、周期重置、无额度信息。
4. 成功、超时、失败、过期缓存、URL 修改、YAML 失败分别测试；代理与定时刷新链路一致。
5. YAML 不变、用量变化时公开订阅返回 200 且卡片更新，Agent 无配置重载；完整→缺失时也更新 ETag。
6. 发布失败/回滚保留正确的参与源清单；GET/HEAD、旧域名跳转、不同输出格式保持一致。
7. 使用真实 Clash Verge Rev 验证用量条及省略 expire 的表现；Shadowrocket 另做兼容验收，不假定所有客户端完全一致。

## 已确认的产品取舍

已批准：只统计启用的订阅；按额度池去重；缺失时不伪造完整总额；到期不同则不向客户端合成一个到期日；失败时有期限地保留旧快照；先展示、后扩展供应商特定的无限额语义。客户端建议刷新间隔保持 1 小时。

## 订阅刷新历史（补充需求）

`GET /api/profiles/:id/history?before=<cursor>` 按新到旧返回分页，每页 20 条，保留最近 30 天、每个订阅最多 100 条。记录首次、手动、定时、配置变更触发的开始/结束时间、耗时、状态、诊断代码及脱敏失败原因。来源配置并发修改时丢弃旧结果并保留记录；工作进程租约被回收时将未完成记录标记为中断。运行中的刷新收到新手动请求时保留待执行任务，不吞掉请求。

历史自该版本上线开始记录，不伪造以前的记录；删除订阅时级联删除历史。记录不存储原始响应、订阅 URL、代理凭据或 YAML 错误片段。历史接口、额度池设置、用量明细均按租户授权。
