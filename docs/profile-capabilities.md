# Profile 能力与身份绑定

Camofy 将「配置内容」和「配置之间的引用」分开。上游仍只需提供普通 Clash YAML；用户在 Camofy 的订阅源或独立 Profile 上维护出口映射，不要求机场添加任何元数据。最终下发给 Mihomo、Clash Verge Rev 等客户端的仍是普通配置，不含 Camofy 的声明。

## 三个概念

- **导出（export）**：Profile 对外提供的具名出口。稳定的 `key` 指向其 YAML 中某个已存在的代理节点或代理组。一个 Profile 可以导出多个出口；修改显示名称不改变身份引用。
- **输入（input）**：Profile 声明需要身份提供的出口。首版支持把出口写入指定代理节点的 `dialer-proxy` 字段，可声明多个不同节点的输入。商店中的规则组件使用同一身份绑定机制选择访问策略。
- **身份绑定（binding）**：身份选择提供者的 Profile ID 和出口 key，也可绑定到身份默认出口，或显式填写最终节点/代理组名称。启用状态、顺序和绑定值都只属于身份，不写回 Profile。

例如，一个订阅源实际包含 `Gateway` 组，用户将 `main` 出口映射到它；另一个独立 Profile 声明 `upstream` 输入，目标是其 `Relay` 节点的 `dialer-proxy`。身份绑定 `upstream → 订阅源/main` 后，生成的 YAML 中才会出现 `dialer-proxy: Gateway`。提供者在身份内排在使用者前后均可，合并顺序仍按原规则决定同名项覆盖及规则顺序。

若订阅包含名为 `Proxies` 的代理组，Camofy 会将它作为约定的 `default` 候选；其他名字不靠模糊匹配猜测用途。用户可修改、添加或覆盖导出。身份只有一个 `default` 候选时可自动选择；多个候选时必须明确指定。自动发现不以机场域名、URL 或特定账号为条件。

## 编译与安全

保存身份前，云端先收集启用的 Profile，再解析有类型的引用，按 YAML 结构填写指定字段，随后按身份顺序合并、验证最终配置并发布。不会执行脚本、表达式，也不会进行全局字符串替换。预览显示「输入 → 最终名称 → 提供者/出口」，并给出最终 YAML。

每个成功发布的 Revision 保存解析快照。订阅刷新若删除了导出的目标、提供者被禁用、不同 Profile 对同名出口形成歧义、引用目标不存在，或代理链形成循环，新的修订不会发布；原订阅地址继续提供最后有效版本，身份显示具体错误。单独编辑声明或身份默认出口也会触发重建。旧身份若不使用能力声明，发布指纹与输出保持不变。

首版输入字段限于 `dialer-proxy`；这是受控的结构化能力，不是通用模板语言。端口、布尔值和其他字段将来可在同一契约上增加类型与字段白名单，不应让客户端解释变量。
