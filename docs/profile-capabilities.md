# Profile 变量与身份绑定

Camofy 的变量是云端编译元数据。订阅源仍只提供普通 Clash YAML；它不需要知道 Camofy。最终给路由器与第三方客户端下发的也是没有变量标记的普通配置。

## 统一模型

| 对象 | 负责什么 |
| --- | --- |
| Profile 输入 `variables` | 声明稳定 key、显示名称、类型、是否必填、可选默认值。订阅源不能声明输入。 |
| Profile 导出 `provides` | 声明稳定 key、类型和从自身 YAML 取值的选择器；订阅源的映射由用户在 Camofy 保存。 |
| 身份变量 `identity_values` | 在单个身份内命名可复用的值，可直接填写或引用 Profile 导出。 |
| 身份与 Profile 关联 `variable_bindings` | 将该 Profile 的每个输入绑定到直接填写的值、身份变量或一个导出变量名；不保存提供方 Profile ID。 |

Profile 本身没有启用状态。一个 Profile 可以被多个身份复用，而每个身份可以绑定不同值。导出只是候选值的**显式声明**；即使只有一个代理组，系统也不会猜测它是“默认出口”。候选发现只帮助选择，保存导出映射才会使它可被引用。

### 自定义 Profile 的模板

在需要值的 YAML **值位置**写引用，建议将占位值引号包围，以保证模板在绑定前也是合法 YAML：

```yaml
mixed-port: '{{camofy.listen_port}}'
ipv6: '{{camofy.enable_ipv6}}'
prepend-proxies:
  - name: Relay
    type: socks5
    server: example.org
    port: 1080
    dialer-proxy: '{{camofy.route}}'
```

作者需分别声明 `listen_port: integer`、`enable_ipv6: boolean`、`route: outbound`，并可声明任意多个其它输入。变量引擎不认识 `dialer-proxy`、`mixed-port` 等具体字段：模板作者在哪里写引用，值就被填在哪里。完整占位值保留数字、布尔、列表、对象等 YAML 类型；字符串内部插值只接受能安全转换成文本的标量。YAML 键不能含变量。未声明引用、缺少必填绑定、类型不符都拒绝发布。订阅源内容是上游不可信数据，**绝不**执行模板替换。

### 导出和身份

Profile 的导出可使用固定值、JSON Pointer 或按集合中的稳定字段定位。例如用户可在订阅详情中选择其 YAML 里的某个代理组，Camofy 保存“`route` 导出 → 此订阅的该组名称”。刷新后若被选目标消失或不唯一，受影响身份保留最后有效发布；不会猜另一个组。

身份的输入绑定有三种来源：直接填写、引用导出变量名、引用身份变量。输入名不必与导出名相同。例如消费方声明输入 `position`，身份关联显式绑定 `position ← target_group`。两个不同订阅可分别在 Camofy 元数据中声明 `target_group = "Gateway"` 和 `target_group = "节点选择"`。身份只启用前者时取得 `Gateway`；停用前者、启用后者时，**同一条绑定**取得 `节点选择`，无需为切换订阅写特例，上游也无需配合。若没有启用的 Profile 提供该变量，或同时有多个提供方，编译报错并保留上一份有效发布。消费方与提供方从不会因同名而自动绑定；身份必须明确选择 `target_group`。

身份变量可以再引用另一身份变量或导出变量；循环引用会在发布前被拒绝。`outbound` 类型只能指向最终组合里唯一的节点或策略组（或 Mihomo 内置策略）。即使导出变量名唯一，若最终配置中同名节点/组由多个 Profile 定义，也拒绝发布。

## 商店包

商店安装后仍是普通 Profile，启用和参数值都属于身份关联。当前商店为声明式**规则包**：它已有的“访问策略”参数按同一套身份输入绑定解析，既可手填，也可引用身份变量或其它 Profile 的导出。规则包版本仍不可变；未来其它包类型需随不可变版本声明自己的输入、导出和模板，不得把用户私有凭据打进公共包。

## 编译、预览和迁移

云端按以下顺序处理：验证声明 → 解析身份依赖和类型 → 将值写入自定义 Profile 的 YAML 结构 → 按身份关联顺序合并 → 验证最终客户端配置 → 原子发布。依赖解析顺序与 YAML 合并顺序互不影响。预览展示每个输入的最终值和绑定来源，并展示合并 YAML；订阅刷新或绑定失效时保留上一份有效 Revision。版本锁不写入解析后的私有变量值。

旧的 `profile_id + 导出名` 绑定在上线时做一次性数据迁移：本来能唯一解析的绑定直接按导出名工作；只有会歧义或错误指向其它提供方的旧绑定，才分配唯一导出名并同步改写对应声明。旧 ID 只为有界的镜像回滚保留为惰性数据，新解析器不依据它选提供方。新绑定和界面只使用导出变量名。旧的自动组名推断和“唯一候选即默认”继续禁止。
