# 账号角色与全局订阅出口设计

状态：已实现角色鉴权、平台代理、全局出口与失败关闭；保留原设计及发布验证要求。

## 目标与边界

- 新账号只能以 `user` 注册；只有私有运维流程可授予 `admin`。
- 管理员共同管理平台订阅出口，普通用户不读取、不创建、不修改代理。
- 所有订阅首次拉取、手动刷新、定时刷新、重试使用同一个全局策略。
- 未选择代理、代理失效或提取失败时停止刷新，保留最后成功配置；绝不回退直连。
- 不改变身份下发给客户端的节点、DIRECT 规则或设备网络出口。
- 这是减少源站暴露面，不是保证源站 IP 永远不可发现；代理供应商必然能看到连接来源。

## 数据模型

| 对象 | 变更 |
| --- | --- |
| users | 增加 `role = user / admin`，数据库默认 user、非空、枚举约束 |
| platform_proxies | 平台级代理，不归任一用户私有；加密配置、版本、创建/修改者和时间 |
| subscription_egress_policy | 单例；选中的代理外键、版本、修改者和时间；空值意味着暂停拉取 |
| admin_audit_events | 管理员操作与结果，记录对象、版本和关联 ID，不记录密钥、原始 URL 或供应商响应 |
| source Profile | 保留原 `proxy_id` 数据用于将来迁移，当前读写接口不暴露、不应用，旧客户端提交该字段不生效 |

现有代理不直接开放跨租户读取。迁移时将选定的现有代理复制为平台代理，保留原数据；管理员共享同一平台列表。全局选中代理受外键保护，必须先切换才能删除。发布者资格与管理员权限分离，管理员不自动获得其他用户配置的读取权限。

## 授权与接口

- `/auth/me` 等账号响应增加 role；注册、个人资料更新不允许客户端写 role。
- 服务器按当前数据库角色检查权限，不依赖前端隐藏或长期缓存的角色声明；降权后下次请求生效。
- `/api/admin/proxies` 及详情、修改、删除、出口预览、白名单确认、测试统一要求 admin。
- `/api/admin/subscription-egress` 管理全局出口，保存要求版本号，避免管理员互相覆盖。
- 旧资源 API 中的 proxy 分支同样拒绝普通用户；不能留下通用 CRUD 绕过路径。
- 普通用户资源列表、保存响应、刷新历史均不包含代理地址、白名单 IP、供应商账号、提取地址及原始错误。`last_proxy` / `last_proxy_at` 不再返回，后续刷新也不再保存。
- 密钥采用只写、脱敏读取。普通用户仅收到“平台订阅出口暂不可用，已保留上次成功配置，请稍后重试。”；刷新历史记录保留事件 ID。管理员变更审计写入数据库，独立审计页面暂未提供。

## 拉取链路

`任务 → 全局出口策略快照 → 提取/解析代理 → 经代理拉取 → 校验 → 发布`

1. 统一入口必须拿到有效的全局代理，不接受 source.proxy_id 或请求参数覆盖。
2. 携趣仍在每次拉取前提取短效 IP；限流在平台级跨副本共享。白名单操作只在管理员配置和确认时执行。
3. HTTP(S)、SOCKS5 路径都禁止失败直连。继续校验目标公网地址、限制响应大小、超时，并禁止自动重定向。
4. 目前代码在云端执行目标 DNS 解析；对用户可控域名，应改为可信 HTTPS DNS 解析后校验并固定目标 IP，避免权威 DNS 直接收到源站的解析请求。解析异常也应失败关闭，不能交给代理自由解析而绕过 SSRF 校验。
5. 每次刷新记录策略版本和代理版本。发布结果前重新检查，变更则丢弃旧结果并重新排队。已经建立的连接不能追溯撤回；紧急出口撤销需要取消在途任务。
6. 不因切换全局出口立即批量刷新全部订阅，避免共享代理额度被瞬时耗尽。自动更新沿用订阅间隔及抖动，不增加无限重试；关闭自动更新的订阅失败后由用户手动重试。任务/数据库错误沿用有间隔的 worker 重试。
7. 平台设置只作用于用户订阅拉取；固定供应商接口、商店同步等外联另行列出允许目标并审计，不能误称全平台所有外联均已匿名。

## 界面

- 普通导航移除“拉取代理”。管理员显示“系统管理 → 订阅出口”。
- 管理页上方是全局生效出口、状态和切换动作，下方是代理列表；详情页集中配置、受限诊断和审计。
- 订阅源表单和详情移除代理选择、代理详情链接和出口地址；必要时仅显示“由平台统一管理”。
- 复用已有 Panel、表单控件、确认对话框和状态组件，不新增页面专属交互效果。

## 发布顺序

1. 可先备份生产库，添加向后兼容 role 字段，在单个事务中登记指定管理员。此步骤本身不改变现有应用授权行为。
2. 实现接口授权、响应白名单、平台代理和唯一拉取策略，完成测试。
3. 备份并迁移既有代理，显式确认全局生效出口；不批量改写订阅的历史 proxy_id，不删除旧数据。
4. 本地构建云端镜像、推送镜像仓库，仅滚动替换云端服务；服务器不构建，不改动其他服务或路由器。
5. 验证管理员、普通用户、既有订阅和设备同步，再恢复/确认调度。未配置出口时宁可暂停刷新，不能直连。

`0005_user_roles.sql` 可在应用发布前手动执行，后续由 SQLx 正常迁移登记；不手工伪造 `_sqlx_migrations`。私有管理员邮箱和身份信息不得写进公开仓库。

`0006_platform_egress.sql` 由新版本启动迁移创建平台表，默认暂停拉取。旧代理不会自动成为平台代理，必须由运维显式选择一个已确认的管理员代理，将其加密 data 原样复制至 platform_proxies，并在同一事务设置 subscription_egress_policy、递增版本及记录审计。不能解密打印凭据，不能自动选择普通用户代理。部署核验前后保存数据库备份和代理 ID/策略版本。

## 必须通过的验证

- 注册伪造 admin、个人资料提权均无效；旧会话降权后不能调用管理接口。
- 普通用户访问新旧代理 API、出口预览、通用 CRUD 全部被拒绝，响应中无 IP/凭据。
- 两个管理员看到同一个代理池，且不能因此读取其他租户的订阅内容。
- 旧 proxy_id 为空、指向其他代理或人为伪造，都不影响实际出口；编辑普通字段也不删除旧值。
- 初次、手动、定时、重试均命中全局代理；代理不可用时测试上游直连请求计数为零。
- 在途切换不会发布旧策略结果；供应商限流与并发任务不耗尽服务资源。
- DNS、IPv6、重定向、内网与元数据地址不能绕过出站限制。
- 普通/管理员桌面与移动端 UI、深链接及刷新行为一致；现有订阅地址和设备绑定不变。
